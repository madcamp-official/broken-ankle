# 몬스터 추격 로직 — 원인과 수정

작성일: 2026-07-30
대상: `Assets/Scripts/Monster/`, `Assets/Scripts/Player/FlashlightOcclusion.cs`
관련 프리팹: `Assets/Prefabs/Monster.prefab`, `Assets/Resources/Nathan.prefab`

증상은 "몬스터가 벽 너머 플레이어를 최단거리로 찾다가 벽에 갇힌다"였다.
원인은 하나가 아니라 세 겹이었고, 셋 다 고쳤다.

---

## 0. 세 줄 요약

1. **방 트리거 볼륨이 벽으로 읽히고 있었다.** 더듬이가 모든 방향을 "막힘"으로 보고해
   몬스터가 물리 스텝마다 방향을 반전했다. 실내에서는 항상.
2. **경로 탐색이 없었다.** 벽 너머 직선으로만 밀었기 때문에 방→복도→방을 갈 수 없었다.
3. **더듬이가 두께 0짜리 광선**이라 폭 0.7 몸통이 1칸 문틀에 낀 채 회복하지 못했다.

---

## 1. 감각과 상태

몬스터는 **소리와 빛으로** 움직인다. 시야 판정(적을 눈으로 본다)은 없다.

```
FootstepNoise / MapDoor / MonsterGrab
    └─> NoiseBus.Emit()
          └─> NoiseEars.OnNoise()      맵 ID 필터 → 거리 필터 → 세기
                └─> MonsterAI.OnHeard()     Suspicion += 0.55 × 세기

FlashlightOcclusion.Lit (켜진 빔 목록)
    └─> MonsterAI.SenseLight()               Suspicion += 0.9 × 세기 × dt
```

### 의심 게이지

| 항목 | 값 |
|---|---|
| 소리당 증가 | `0.55 × 세기` |
| 피격 조명 초당 증가 | `0.9 × 세기` |
| 초당 감소 | `0.22` |
| 추격 문턱 | `0.75` |

발소리 한 번은 최대 0.55 → 문턱 미달. 약 2.5초 안에 또 소리를 내면 추격 확정.
빔은 정면 근거리에서 약 1.1초, 빔 끝자락에서는 감쇠가 이겨 영영 걸리지 않는다.

### 상태 전이

```
                  소리/빛 (합계 < 0.75)
   Patrol ────────────────────────────► Alert
      ▲                                   │ 게이지 0.75 돌파
      │ 게이지 소진                        ▼
      └──────────────────────────────  Chase  ◄── 수색 중 새 자극
      ▲                                   │ 도착 또는 경로 소진
      │ 6초 경과                           ▼
      └──────────────────────────────  Search
```

`Alert`은 `Steer()`가 `Vector2.zero`를 반환해 완전히 멈춰 선다.

## 2. 원인

### 2-1. 방 트리거 볼륨이 벽으로 읽힘 ★ 직접 원인

그레이박스 빌더는 방마다 카메라용 트리거 볼륨(`RoomBounds`)을 깐다.

| 사실 | 값 | 출처 |
|---|---|---|
| 방 볼륨 레이어 | 0 (Default) | `AshburnGreyboxBuilder.MakeRoom` |
| 방 볼륨 크기 | 방 전체 | 〃 |
| 몬스터 `obstacles` | 55 (레이어 0 포함) | `Monster.prefab` |
| `m_QueriesHitTriggers` | 1 | `Physics2DSettings` |
| `m_QueriesStartInColliders` | 1 | 〃 |

`Physics2D.Raycast`가 방 볼륨을 **거리 0에서** 맞는다. 자기 자식이 아니므로 필터도 통과한다.
결과적으로 세 방향 더듬이가 전부 "막힘"을 반환하고, 매 `FixedUpdate`마다

```csharp
desired = -desired;          // 옛 MonsterAI.cs:200
_patrolDirection = desired;
```

로 떨어졌다. 물리 스텝마다 방향 반전 → 제자리 진동. **방 안에 있는 한 언제나.**
문틀까지 갈 것도 없이 방 한가운데서 이미 갇혀 있었다.

### 2-2. 경로 탐색 부재

`Chase`는 매 프레임 `Destination = _lastNoisePosition`으로 덮어썼다.
**"일단 문까지 간 다음 다시 생각한다"는 중간 목표를 가질 구조가 없었다.**

### 2-3. 두께 0 광선 vs 폭 0.7 몸통

| 항목 | 값 |
|---|---|
| `cellSize` | 1.0 |
| 출입구(`+`) 폭 | 1.0 |
| 몬스터 캡슐 | 0.7 × 0.34 (가로) |
| 양쪽 여유 | 0.15씩 |

```
      벽   ┌─┐     ┌─┐   벽
           │ │  ╱  │ │        ← 광선(굵기 0)은 대각선으로 통과
      ═════┘ ╱     └═════
        ┌──╱──┐               ← 몸통(0.7)은 문설주에 걸림
        │ 몬  │
        └─────┘
```

광선이 계속 뚫려 있다고 말하므로 회피 분기가 발동조차 하지 않는다. 영구 정지.

### 2-4. 좌우 선택에 근거·기억 없음

`if (!Blocked(left)) ... else if (!Blocked(right))` — 항상 왼쪽 우선이고 직전 프레임을
기억하지 않아, 벽 형상이 바뀌면 좌우가 뒤집혀 진동했다.

### 2-5. 발소리가 실제 이동이 아니라 명령 속도 기준

벽에 낀 몬스터가 제자리에서 계속 발소리를 냈다. 플레이어 화면에는 한 지점에서
빨간 링이 계속 깜빡였다.

### 2-6. 자기 콜라이더 자가 히트 (잠재)

`Raycast`는 가장 가까운 하나만 반환한다. 시작점이 자기 콜라이더 안이면 자기 자신이
반환되고, `IsChildOf` 필터를 거쳐 "안 막힘"이 된다. 프리팹의 `obstacles = 55`가
Actor 레이어를 빼서 우연히 막고 있었을 뿐, 필드 기본값은 `~0`이었다.

### 2-7. `nest` 미설정 시 조용히 굳음

`MonsterGrab.nest`가 비면 잡는 순간 AI가 꺼지고 `FixedUpdate`가 즉시 return한다.
몬스터가 그 자리에 굳는데, 이게 경로 탐색 버그와 똑같이 보인다.

### 2-8. 끌고 가는 동안 완전 무음

`MonsterGrab`이 `_ai.enabled = false`로 AI를 끄면 소음 방출도 함께 꺼졌다.
`MonsterGrab`의 클래스 주석은 *"the trip home is deliberately slow and noisy enough
to be followed"*라고 적혀 있다. **문서화된 의도와 정반대**였고, 동료를 구하러 가야 하는
유일한 구간이 집에서 제일 조용했다.

## 3. 수정 내용

### 3-1. `NavGrid.cs` 신규 — 격자 A*

맵당 하나, 로드 시 1회 생성. `MapZone` 단위로 캐시해 여러 몬스터가 공유한다.

**격자 생성은 콜라이더 bounds 래스터화.** 셀마다 물리 쿼리를 던지는 방식도 검토했으나
Street 규모에서 4만 회가 넘어 로드 히칭이 된다. 벽이 전부 축정렬 박스라 bounds가 곧
형상이므로 산술로 정확히 굽는다.

- **장애물을 몸 반지름만큼 부풀려서** 표시한다. "통과할 수 있나"가 "이 칸이 비었나"로
  바뀌므로, 1칸 문 경로는 몸이 실제로 따라갈 수 있는 경로다.
- **셀 0.25칸.** 반지름 0.35 몸이 1.0칸 문에서 갖는 자유 대역이 0.3이고,
  0.25 간격 샘플은 폭 0.3 대역 안에 항상 하나 들어간다.
- **트리거 제외** — 2-1의 방 볼륨. **비정적 Rigidbody2D 제외** — 로드 순간 서 있던
  캐릭터가 기둥으로 구워지는 것을 막는다.
- 8방향, 대각선 코너 컷 방지(양쪽 직교 이웃이 모두 열려야 대각 허용).
- 직선 구간 압축 + 제한 시야 스트링 풀링으로 셀 중심 지그재그 제거.
- 세대 스탬프로 배열 재사용, 이진 힙. 재탐색마다 맵 크기 배열을 지우지 않는다.
- 출발·도착 지점은 `TryNearestFree`로 스냅한다. 벽에 붙은 몬스터의 중심은 자기 반지름이
  막아 놓은 대역 안에 있으므로, 스냅이 없으면 가장 필요한 순간에 경로가 안 나온다.

**좌표 정렬 주의.** 격자는 콜라이더 bounds에서 자기 원점을 유도한다.
빌더의 `WorldOf()`·`layoutOffset`·`MapZone` 슬롯 이동에 의존하지 않으므로
반 칸 어긋남 문제가 생기지 않는다.

### 3-2. 더듬이를 `CircleCast`로

- 반지름 `0.85 × 몸 반지름`. 문틀 끼임이 사라진다.
- `ContactFilter2D { useTriggers = false }` — **2-1의 직접 수정.**
- 모든 히트를 검사한다. 자기 히트 하나가 뒤를 가리는 2-6이 구조적으로 사라진다.
- `obstacles` 필드 기본값 `~0` → `1`. 프리팹의 55는 그대로 두어도 이제 정상 동작한다.

A*가 정적 벽을 담당하므로 더듬이의 역할은 **동적 장애물 전용**으로 축소됐다.

### 3-3. 회피 휴리스틱

- 미끄러지는 방향을 `_slideSign`에 기억하고, 막혀 있는 동안 유지한다.
- 30 / 55 / 85 / 120 / 155° 를 **한쪽 먼저 전부** 시도한 뒤 반대쪽으로 넘어간다.
- 180° 반전은 10방향이 모두 막혔을 때만.

### 3-4. 실제 이동량 기준 + 끼임 감지

- 직전 물리 스텝 대비 실제 변위로 `Speed`를 측정한다. 발소리·연출이 전부 이 값을 본다.
- 명령 속도는 큰데 실제 변위가 25% 미만인 상태가 0.4초 지속되면 끼임으로 보고,
  미끄럼 방향을 반전하고 재탐색한다.
- `Arrived`에 **경로 소진** 조건을 넣었다. 도달 불가능한 지점(잠긴 문 너머 등)에서
  영원히 벽을 밀지 않고 `Search`로 넘어간다.

### 3-5. 순찰이 실제 목적지를 고름

3칸 앞 임의점(벽 속일 수 있음) 대신 `TryNearestFree`로 스냅한 4~9칸 목적지를 잡는다.
순찰이 집을 돌아다니게 됐다.

### 3-6. 손전등에 비추이면 추격

`FlashlightOcclusion`에 켜진 빔 정적 목록과 `Illuminates(point, out strength)`를 추가했다.

**새 레이캐스트를 쏘지 않는다.** 이 컴포넌트는 이미 매 프레임 콘 반각과 벽에 막힌 지점까지의
거리(`_rayReach`, 96갈래 부채꼴)를 계산해 쿠키 텍스처를 깎고 있다. 그 데이터를 그대로 질의한다.

```
빔 로컬 변환 → local.y ≤ 0        뒤쪽, 탈락
            → |각도| > 반각        콘 밖, 탈락
            → 거리 > _rayReach[갈래]  벽 뒤, 탈락
            → strength = 1 - 거리/사거리
```

렌더러의 `Redraw`가 쓰는 것과 같은 공식이다. 따라서 **화면에 보이지 않는 빛에 걸리지 않는다.**
빔 오브젝트가 토글로 `SetActive(false)` 되므로 `OnEnable/OnDisable` 등록만으로
"꺼진 손전등은 목록에 없음"이 성립한다.

소리와 결정적으로 다른 점: **소리는 소리가 난 곳을, 빛은 든 사람이 선 곳을 알려준다.**
비추는 동안 몬스터의 목적지가 플레이어를 계속 따라간다. 이것이 손전등의 대가다.

맵 검사는 기하 검사보다 먼저 한다. `NoiseEars`가 거리보다 맵을 먼저 보는 것과 같은 이유.

### 3-7. 가만히 있어도 소리를 냄

`EmitFootsteps` → `EmitOwnNoise`. 걷든 서 있든 한 곳에서 결정하므로 두 타이머가 겹치지 않는다.

| | 사거리 | 간격 |
|---|---|---|
| 이동 중 | 14 | 속도 비례 0.15~0.7초 |
| 정지 | 8 | 2.2초 ± 35% |

정지 사거리를 짧게 잡은 것은 의도다. 발소리가 아니라 숨소리이고, "집 건너편"이 아니라
"이 방 어딘가"를 알려주는 정보여야 한다. 지터는 규칙적이면 플레이어가 곧 무시하기 때문.

멈춰 서서 노려보는 `Alert`에서도 울린다. 가장 긴장되는 순간이라 그대로 뒀다.

### 3-8. 끄는 소리 (2-8 해결)

`MonsterGrab`이 자체 드래그 소음을 낸다. 사거리 12, 0.55초 간격.

### 3-9. `nest` 누락을 소리 나게 실패시킴

`Awake`에서 에러 로그, 그리고 `nest`가 없으면 잡지 않는다.
통과해 지나가는 것은 눈에 보이는 버그지만, 얼어붙는 것은 다른 버그로 위장한다.

## 4. 튜닝 값

전부 인스펙터 노출. 기본값은 다음과 같다.

| 필드 | 값 | 비고 |
|---|---|---|
| `suspicionPerLitSecond` | 0.9 | **0이면 빛에 무감각**. 예전 동작 |
| `navCellSize` | 0.25 | 통과시킬 최소 틈보다 작아야 한다 |
| `agentRadius` | 0 | 0이면 콜라이더에서 자동 측정 |
| `repathInterval` | 0.35초 | |
| `repathTolerance` | 0.75칸 | 목표가 이만큼 밀리면 조기 재탐색 |
| `stuckPatience` | 0.4초 | |
| `idleRange` / `idleInterval` | 8 / 2.2초 | |
| `dragNoiseRange` / `dragNoiseInterval` | 12 / 0.55초 | `MonsterGrab` |

`suspicionPerLitSecond`는 실제로 플레이해 보면 조정 대상이다. 너무 빠르면 손전등을
못 쓰는 게임이 되고, 너무 느리면 켜고 다녀도 무해해진다.

## 5. 범위에서 제외 — 건물 안팎 추적

**몬스터는 자기가 배치된 씬 밖으로 나갈 수 없다.** 버그가 아니라 현재 아키텍처의 결과이고,
바꾸려면 게임 디자인 결정이 필요해 손대지 않았다.

**(1) 소리가 맵 경계를 못 넘음**
`NoiseEars.OnNoise()`는 거리를 재기 전에 맵 ID부터 비교하고 다르면 버린다.
House와 Street는 별개 씬이며 `MapZone`이 서로 다른 슬롯(1000단위)을 잡는다.

**(2) 맵을 옮길 수단이 없음**
`Monster.prefab`에 `MapPresence`가 없어 `MapZone.IdOf()`가 부모 `MapZone`으로 폴백한다.
`MapTravel.Go()` 호출부는 `MapDoor.Interact(interactor)` 하나뿐이고, 이는 `PlayerInteractor`가
상호작용키로 부르는 경로다. 문은 트리거도 아니라 몬스터가 밟아도 무반응.

구현하려면 몬스터에 `MapPresence`를 붙이고, `MapLoader` 참조 카운트에 몬스터를 참여시키고
(플레이어 없는 맵을 몬스터 때문에 유지할 것인가), 문을 쓸 수 있게 하고, 플레이어 없는 맵의
몬스터를 계속 시뮬레이션할지 정해야 한다.

### 부작용 하나 — 의도 확인 필요

`MapDoor.Interact`는 열리든 안 열리든 9칸짜리 소리를 **문이 속한 맵** 태그로 쏜다.
House 안쪽 `D`에서 플레이어가 나가면 그 소리는 House 태그다.

> 몬스터는 문 여는 소리를 듣고 달려오지만 따라 나갈 수는 없다.

연출로 의도한 것이라면 그대로 두면 된다.

## 6. 검증 상태

### 통과한 것

`NavGrid.cs` 원본을 UnityEngine 셰임과 함께 컴파일해 House 레이아웃으로 돌렸다.
2-1의 방 트리거 볼륨도 재현해 포함했다. 격자 180×60, 7개 케이스 전부 통과.

```
nest -> far corridor        2 waypoints, 36.0 units   ← 보고된 시나리오
nest room -> left room      3 waypoints, 40.2 units
room -> doorway -> corridor 1 waypoints,  4.0 units   ← 1칸 문 통과
off-centre approach         3 waypoints,  9.7 units   ← 비스듬한 진입
goal inside a wall          2 waypoints, 28.1 units   ← 목표 스냅
starting against a wall     2 waypoints, 31.6 units   ← 출발 스냅
spawn -> nest               2 waypoints, 38.0 units
```

각 구간은 `IsClear`로 몸 크기 기준 재검증했다.

### 아직 확인 안 된 것

**에디터 실기 검증.** 위는 알고리즘 검증이지 플레이 검증이 아니다.

1. **방 → 복도 → 다른 방.** 몬스터를 둥지(`N`)에 두고 플레이어가 반대편 방에서 뜀.
   플레이 중 몬스터를 선택하면 `OnDrawGizmosSelected`가 주황색 경로를 그린다.
2. **1칸 문 통과.** 정중앙이 아닌 각도로 접근시켜도 통과하는지.
3. **북쪽 이동.** 2-6 회귀 확인.
4. **끼임 복구.** 일부러 구석에 몰아넣고 빠져나오는지.
5. **발소리.** 벽에 막힌 상태에서 빨간 링이 멈추는지.
6. **손전등.** 정면 1초 남짓에 추격이 붙는지. **벽 뒤 몬스터에 겨눠도 무반응인지.**
   끄면 즉시 무반응인지.
7. **정지 소음.** 멈춘 몬스터가 2초쯤마다 빨간 링을 띄우는지.
8. **끌기 소음.** 잡힌 뒤 몬스터가 계속 들리는지.
