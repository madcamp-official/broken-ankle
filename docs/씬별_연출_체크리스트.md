# 씬별 연출 체크리스트

`docs/대사_연출안.md`를 실제 Unity 씬에 적용하기 위한 배치/디자인/시스템 체크리스트다.

목표는 대사를 먼저 넣는 것이 아니라, 각 장면이 플레이어 눈에 어떻게 보이고 어떤 조작 상태로 진행되는지 먼저 고정하는 것이다.

## 0. 공통 규칙

| 항목 | 기준 |
|---|---|
| 대사 UI | 하단 검은 대사창, 좌측 이름, 우측 초상화, TextMeshPro |
| 입력 잠금 | 중요한 연출 중 이동/상호작용 잠금, 대사 넘김만 허용 |
| 완료 플래그 | 같은 이벤트가 반복 재생되지 않도록 `WorldState`에 eventId 저장 |
| 소음 연출 | 대사, 발소리, 문소리, 장비음은 몬스터 반응과 연결 |
| 카메라 | 공포 장면은 줌인/흔들림/강제 시선 유도 사용 |
| 조명 | 손전등 원, 조명 깜빡임, 화면 암전으로 시선 제어 |

권장 시스템 구조:

| 컴포넌트 | 역할 |
|---|---|
| `DialogueTrigger` | 특정 위치/조건에서 대사 이벤트 실행 |
| `DialogueManager` | 대사창 표시, 타자기 효과, 다음 문장 처리 |
| `CutsceneController` | 입력 잠금, 카메라, 자동 이동, 몬스터 활성화 호출 |
| `EventFlagStore` 또는 `WorldState` | 이벤트 완료 여부와 문서 습득 여부 저장 |
| `NoiseEventEmitter` | 대사/연출 소리를 몬스터 AI에 전달 |

### 기믹용으로 실제 만들어 둔 컴포넌트

| 컴포넌트 | 역할 |
|---|---|
| `FlaggedDialogue` | 플래그가 올라간 순간 대사 재생. 바닥의 선을 이미 지나간 짝에게도 장면이 온다 |
| `WorldFlagAll` | 여러 플래그가 다 차면 결과 플래그 하나를 올린다. 두 사람이 순서 없이 각자 끝내는 구조 |
| `RepairTask` | 붙잡고 있어야 끝나는 설비 작업. 역할 제한, 작업 중 소음, 완료 플래그 |
| `SearchableCache` | 여러 후보 중 하나에만 물건이 있는 탐색. 헛수고는 짧은 대사와 소음으로 갚는다 |
| `TilemapDoor` | 멀리서 열리는 문. 닫힌 타일맵과 열린 타일맵을 맞바꾸고 막이를 끈다 |
| `PlayerRole` | 슬롯으로 네이선(0)/그랜트(1)를 가른다. 기록은 네이선, 설비는 그랜트 |

역할 제한은 `DialogueInteractable`, `RepairTask`, `SearchableCache` 의 `Required Slot` 에
있다. `-1` 은 누구든, `0` 은 네이선, `1` 은 그랜트다. 상대가 오면 프롬프트가
"그랜트 담당이다" 처럼 바뀌고 상호작용만 막힌다 — 프롬프트까지 사라지면 여기에
아무것도 없는 것처럼 보이기 때문이다.

## 1. 시작 TV 브리핑

### 목적

플레이어에게 임무, 헤드셋 기능, 초록색 소음링의 의미를 설명하면서 센틸을 처음에는 정상적인 회사처럼 보이게 한다.

### 씬

`Container Box`

### 필요한 배치

| 요소 | 배치 |
|---|---|
| TV 오브젝트 | 컨테이너 중앙 또는 상단 벽 근처 |
| Nathan/Grant | TV 앞에 나란히 서 있음 |
| 시작 카메라 | TV 화면 클로즈업 |
| 종료 카메라 | TV에서 줌아웃해 컨테이너 내부 표시 |
| CRT 노이즈 UI | TV 화면 위 오버레이 |

### 디자인 체크

| 체크 | 내용 |
|---|---|
| TV 화면 | 센틸 로고, 회색/녹색 계열 텍스트, 노이즈 |
| 초록색 강조 | "초록색" 단어만 실제 초록색으로 표시 |
| 불길한 암시 | 브리핑 중 0.2초 정도 구조 요청 자막이 끼어듦 |
| 대사창 | TV 브리핑 중에는 일반 대사창보다 방송 자막처럼 처리 가능 |

### 시스템 체크

| 체크 | 내용 |
|---|---|
| 시작 버튼 후 | `intro_tv_001` 실행 |
| 입력 | 브리핑 중 잠금 |
| 종료 | `container_start_001` 실행 후 이동 가능 |
| 플래그 | `IntroTvPlayed = true` |

### 필요한 배치

### 시스템 체크

| 체크 | 내용 |

## 3. 병원 조사

### 목적

화재 사고인데 청각 손상/음향 상쇄 기록이 많다는 이상함을 보여준다.

### 씬

`Hospital`

### 필요한 배치

| 요소 | 배치 |
|---|---|
| 접수 카운터 | 진입 직후 보이는 위치 |
| 접수 카드 | 접수실 바닥. `Key_HospitalCard`, 키 이름 `HospitalCard` |
| 기록 보관실 문 | 대기실 → 기록 보관실. `Door_Records`, 카드로만 열린다 |
| 서가 여섯 | 기록 보관실 북쪽 벽. `SEARCH_hospital_records` 아래 `Shelf_1..6` |
| 꺼진 모니터 | 접수/응급실에 배치 |
| 보조 사운드 | 심박음, 형광등 잡음, 멀리서 휠체어 끄는 소리 |

### 디자인 체크

| 체크 | 내용 |
|---|---|
| 병원 분위기 | 피보다 "기록이 이상하게 정리된 장소" 느낌 |
| 문서 가독성 | 손전등을 비추면 핵심 단어만 보이게 연출 |
| 라벨 | 서가 라벨이 전부 떨어져 있어야 한다. 어느 칸인지 밖에서 알 수 없는 것이 기믹이다 |
| 헛수고의 값 | 빈 서랍도 소음을 낸다. 여섯 번 다 여는 것이 안전한 선택이 아니어야 한다 |

### 시스템 체크

| 체크 | 내용 |
|---|---|
| 진입 대사 | `hospital_enter_001` |
| 문 해금 | `Key_HospitalCard` 습득 → `Door_Records` → `door:Hospital_Records` |
| 보관실 진입 | `hospital_records_room_001` |
| 서가 탐색 | `SearchableCache`. 빈 칸은 `hospital_shelf_empty_001..004` 를 돌아가며 재생 |
| 기록 발견 | 여섯 중 하나에서만 `hospital_record_001` |
| 어느 칸인가 | 방 이름 해시로 뽑는다. 두 기기가 통신 없이 같은 답을 낸다 |
| 진행 해금 | 경찰서 목적지 활성화 |
| 플래그 | `HospitalRecordRead`, `cache:hospital_records` |

된다.

## 7. 격납고 대량 활성화

### 목적

소음 관리자가 한 마리가 아니라 대량 생산된 장치였다는 스케일 반전을 준다.

### 씬

`Greybox_Hanger` 또는 `Corp_Basement` 이후 격납고

### 필요한 배치

| 요소 | 배치 |
|---|---|
| 비활성 소음 관리자들 | 줄지어 선 형태로 넓게 배치 |
| Nathan 사무실 | 버튼, 소음 관리자 문서 |
| Grant 전력실 | 미니게임 패널 |
| 열린 문 | Nathan 버튼 후 Grant가 들어갈 수 있는 방 |
| 탈출문 | 활성화 후 도망칠 방향이 명확한 문 |

### 디자인 체크

| 체크 | 내용 |
|---|---|
| 첫 화면 | 격납고 진입 시 정지한 소음 관리자 군집이 보여야 함 |
| 버튼 | 누르기 꺼림칙한 디자인, 긁힌 자국 |
| 활성화 | 조명이 행 단위로 켜지고 몬스터 머리가 순서대로 돌아감 |
| 압박감 | 붉은 소음링 여러 개가 화면에 겹쳐짐 |

### 시스템 체크

| 체크 | 내용 |
|---|---|
| 진입 대사 | `hangar_enter_001` |
| 사무실 | 우측 상단 방(셀 x 11–27, y 1–12). 큰 책상이 x 18–21, y 3–10 |
| 버튼 | `DOC_hangar_button` @ (18.5, 6.5) 책상 위. 네이선이 E → `hangar_button_001` → `HangarButtonPressed` |
| 아래쪽 방 문 | `LOCK_hangar_powerroom`. `Tilemap_Door_Closed` 의 (10,-6) 을 지우고 `Tilemap_Door_Opened` 의 (11,-6),(11,-5) 를 세운다. 막이는 `BLOCK_hangar_powerroom` |
| 전력실 | 우측 하단 방. `TASK_hangar_power` @ (14.5, -8.5), 5초 홀드, 그랜트 전용 → `HangarPowerFixed` |
| 문서 | `DOC_hangar_warden_doc` @ (24.5, 12.5) 사무실 캐비닛. 네이선 전용 → `WardenDocRead` |
| 전력만 완료 | `hangar_power_ready_001` |
| 문서+전력 완료 | `WorldFlagAll` → `Story:HangarAwakened` → `hangar_awakening_001` |
| 탈출문 | 각성 전에는 `Block_MoveToOut_Hanger` 가 막고 `Trigger_MoveToOut_Hanger` 도 잠겨 있다. 각성과 함께 둘 다 풀린다 |
| 플래그 | `HangarButtonPressed`, `HangarPowerFixed`, `WardenDocRead`, `Story:HangarAwakened` |

버튼과 문이 다른 방에 있는 것이 요점이다. 네이선은 자기가 무엇을 열었는지 볼 수
없고, 그랜트는 문이 열리는 소리로만 안다. 각성 대사는 트리거가 아니라 플래그로
재생되므로, 두 사람이 어디에 서 있든 같은 순간에 온다.

## 8. 시청 2층 은신

### 목적

후반부 규칙 변화. 플레이어가 웅크리기를 실제 생존 조건으로 사용하게 한다.

### 씬

`Greybox_CityHall_2F`

### 필요한 배치

| 요소 | 배치 |
|---|---|
| 순찰 소음 관리자 | 복도/방을 오가는 다수 배치 |
| 낮은 엄폐물 | 책상, 캐비닛, 파티션 |
| 좁은 통로 | 웅크려서 지나가야 안정적인 동선 |
| 경고 구역 | 달리면 바로 추적되는 긴 복도 |

### 디자인 체크

| 체크 | 내용 |
|---|---|
| 웅크리기 안내 | 대사로만 설명하지 말고 몬스터 반응으로 보여줌 |
| 소리 피드백 | 걷기/달리기/웅크리기별 소음링 크기가 다르게 보임 |
| 압박 | 목적지는 보이지만 빠르게 갈 수 없는 구조 |

### 시스템 체크

| 체크 | 내용 |
|---|---|
| 도착 대사 | `cityhall_2f_crouch_001` |
| 웅크리지 않음 | 근처 몬스터 경계 또는 추적 |
| 달리기 | 즉시 광역 경보 |
| 진행 | 3층 계단/문까지 도착 |

## 11. 씬 작업용 최소 오브젝트 이름

씬에 임시 오브젝트를 둘 때 아래 이름을 쓰면 나중에 스크립트 연결이 쉬워진다.

| 이름 | 용도 |
|---|---|
| `TRG_Dialogue_<eventId>` | 대사 트리거 |
| `CUT_Waypoints_<eventId>` | 자동 이동 경로 부모 |
| `ACT_Monster_<eventId>` | 연출용 몬스터 |
| `DOC_<documentId>` | 문서 상호작용 |
| `LOCK_<doorId>` | 잠금/해제 문 |
| `SFX_<eventId>` | 위치 기반 사운드 |
| `CAM_Focus_<eventId>` | 카메라 포커스 지점 |

예시:

| 오브젝트 이름 | 적용 장면 |
|---|---|
| `TRG_Dialogue_corp_first_warden_001` | 회사 첫 조우 |
| `CUT_Waypoints_corp_escape_001` | 회사 자동 도주 |
| `DOC_noise_system` | 회사 2층 소음 관리 시스템 문서 |
| `DOC_warden_spec` | 격납고 소음 관리자 문서 |
| `LOCK_corp_floor2_stairs` | 회사 2층 계단실 |
| `CAM_Focus_hangar_rows` | 격납고 군집 최초 노출 |
